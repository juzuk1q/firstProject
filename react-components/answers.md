# Ответы на вопросы для самоконтроля: Практическая работа №15 («React: создание компонентов»)

---

### 1. В чем разница между функциональными и классовыми компонентами в React? Когда следует использовать каждый тип?

| Критерий | Функциональные компоненты | Классовые компоненты |
| :--- | :--- | :--- |
| **Синтаксис** | Простые функции JavaScript, принимающие `props` и возвращающие JSX. | ES6-классы, наследующиеся от `React.Component`, с обязательным методом `render()`. |
| **Управление состоянием** | Хуки `useState`, `useReducer`. | Свойство `this.state` и метод `this.setState()`. |
| **Жизненный цикл** | Хуки эффектов (`useEffect`, `useLayoutEffect`). | Методы жизненного цикла (`componentDidMount`, `componentDidUpdate`, `componentWillUnmount` и др.). |
| **Ключевое слово `this`** | Не используется (нет проблем с привязкой контекста `bind`). | Требует постоянного обращения к `this.props`, `this.state`, ручной привязки методов в конструкторе или arrow functions. |
| **Объем кода** | Лаконичные, легко тестируются, меньше шаблонного кода (boilerplate). | Более громоздкий синтаксис. |

**Когда что использовать:**
- **Функциональные компоненты с хуками** — абсолютный современный стандарт разработки в React (начиная с версии 16.8+). Их следует использовать для **всех новых компонентов**.
- **Классовые компоненты** используются преимущественно для поддержки старых кодовых баз (legacy), а также для создания **Error Boundaries** (предохранителей ошибок), так как методы `componentDidCatch` и `getDerivedStateFromError` на данный момент не имеют прямых эквивалентов среди хуков.

### 2. Что такое props и state? Как они отличаются и какие правила их использования?

- **`props` (свойства)**: входные параметры, передаваемые в компонент извне (от родителя к потомку). Являются **иммутабельными (read-only)** — компонент никогда не должен изменять свои собственные `props`.
- **`state` (состояние)**: внутреннее приватное хранилище данных компонента, которое контролируется и изменяется самим компонентом в процессе его жизненного цикла.

| Характеристика | `props` | `state` |
| :--- | :--- | :--- |
| **Откуда поступают** | Из родительского компонента | Инициализируются внутри компонента |
| **Возможность мутации** | Только для чтения (иммутабельны) | Изменяются через `setState` / `setCount` |
| **Влияние на рендер** | При изменении `props` компонент ререндерится | При изменении `state` компонент ререндерится |

**Правила использования:**
1. Нельзя изменять `props` напрямую (принцип чистых функций).
2. Нельзя мутировать `state` напрямую (`this.state.count = 5` или `state.push(item)` запрещены). Обновление должно происходить только через функцию установки состояния, возвращая новый объект или массив.

### 3. Как работает поднятие состояния (lifting state up) и в каких ситуациях это необходимо?

В React данные передаются сверху вниз (однонаправленный поток данных). Если двум или более дочерним компонентам на одном уровне требуется доступ к одним и тем же данным или они должны влиять на отображение друг друга, общее состояние **«поднимается» до их ближайшего общего предка**.

Родительский компонент:
1. Хранит само состояние (`state`).
2. Передает актуальное значение вниз дочерним компонентам через `props`.
3. Передает дочерним компонентам функции обратного вызова (колбэки), чтобы они могли уведомить родителя о необходимости изменить состояние.

**Когда необходимо:**
- Синхронизация двух полей ввода (например, конвертер валют "Рубли <-> Доллары" или шкалы "Цельсий <-> Фаренгейт").
- Фильтрация и поиск: компонент `<SearchBar />` вводит строку, а компонент `<ProductList />` фильтрует товары.
- Корзина интернет-магазина и счетчик товаров в шапке сайта.

### 4. Какие методы жизненного цикла классовых компонентов вы знаете и для чего они используются?

Жизненный цикл делится на 3 фазы:

1. **Монтирование (Mounting)**:
   - `constructor()`: инициализация начального `this.state` и привязка методов.
   - `static getDerivedStateFromProps()`: синхронизация состояния с пропсами перед рендером.
   - `render()`: формирование виртуального DOM (чистая функция).
   - `componentDidMount()`: выполняется сразу после первой вставки в DOM. Идеально для сетевых запросов (`fetch`), установки таймеров и подписки на глобальные события (`window.addEventListener`).
2. **Обновление (Updating)**:
   - `shouldComponentUpdate(nextProps, nextState)`: оптимизация рендеринга (возврат `false` отменяет ререндер).
   - `render()`: повторный рендер интерфейса.
   - `getSnapshotBeforeUpdate(prevProps, prevState)`: захват свойств DOM (например, позиции скролла) перед его обновлением.
   - `componentDidUpdate(prevProps, prevState)`: выполняется после обновления DOM. Используется для повторных сетевых запросов при смене `props`.
3. **Размонтирование (Unmounting)**:
   - `componentWillUnmount()`: вызывается перед удалением компонента из DOM. Обязателен для очистки таймеров (`clearInterval`), отмены подписок и сетевых запросов для предотвращения утечек памяти.

### 5. Как работают хуки useState и useEffect? Какие правила использования хуков существуют?

- **`useState(initialValue)`**: объявляет переменную состояния. Возвращает кортеж из двух элементов: текущее значение состояния и функцию для его обновления.
- **`useEffect(callback, dependencies)`**: выполняет побочные эффекты (side effects): запросы к API, подписки, манипуляции с DOM. Может возвращать функцию очистки (`cleanup function`). Зависимости определяют частоту запуска:
  - Без массива: на каждый рендер;
  - `[]`: один раз при монтировании;
  - `[prop, state]`: при изменении указанных значений.

**Правила хуков:**
1. **Только на верхнем уровне**: нельзя вызывать хуки внутри циклов, условий (`if`) или вложенных функций. React полагается на строгий порядок вызова хуков между рендерами.
2. **Только из функций React**: хуки вызываются только из функциональных компонентов или кастомных хуков.

### 6. Что такое ключи (keys) в React и почему они важны при рендеринге списков?

**`key`** — это специальный строковый или числовой строковый пропс, который необходимо указывать при рендеринге списков элементов (`map`).

**Зачем они нужны:**
React использует алгоритм согласования (**Reconciliation / Diffing algorithm**). Ключи помогают React идентифицировать, какие именно элементы в списке изменились, были добавлены или удалены.

- **Если ключи стабильны и уникальны (например, `id` из базы данных)**: React переиспользует существующие DOM-узлы и переставляет только изменившиеся элементы, что гарантирует высокую производительность и сохранение состояния инпутов.
- **Если ключи — индексы массива (`key={index}`)**: при удалении или вставке элементов в начало или середину списка индексы смещаются, что приводит к некорректному сохранению внутреннего состояния полей ввода и лишним DOM-мутациям.

### 7. Как обрабатывать события в React и чем это отличается от нативного JavaScript?

1. **Синтаксис именования**: в React события именуются в camelCase (`onClick`, `onSubmit`, `onMouseEnter`), а не в нижнем регистре (`onclick`).
2. **Передача обработчика**: в JSX передается ссылка на функцию (`onClick={handleClick}`), а не строка (`onclick="handleClick()"`).
3. **Синтетические события (`SyntheticEvent`)**: React оборачивает нативные события браузера в кроссбраузерную обертку `SyntheticEvent`, обеспечивая идентичное поведение во всех браузерах.
4. **Предотвращение стандартного поведения**: в React нельзя просто вернуть `false` из функции. Для отмены отправки формы или перехода по ссылке необходимо явно вызвать `e.preventDefault()`.

### 8. Что такое управляемые и неуправляемые компоненты? В чем их разница?

- **Управляемые компоненты (Controlled)**: данные формы контролируются состоянием React (`useState`/`this.state`). Значение инпута задается через атрибут `value`, а изменения отслеживаются через `onChange`. React является единственным источником истины.
- **Неуправляемые компоненты (Uncontrolled)**: данные формы хранятся непосредственно в DOM-дереве браузера. Для доступа к их значению используются ссылки (`ref` / `useRef`), а начальное значение задается через `defaultValue`.

### 9. Как работает контекст (Context) в React и когда его следует использовать?

**Context API** предоставляет способ передавать данные через дерево компонентов без необходимости прокидывать пропсы вручную на каждом уровне (решение проблемы `prop drilling`).

**Механизм работы:**
1. `React.createContext()`: создание контекста.
2. `<Context.Provider value={...}>`: оборачивает родительское поддерево и предоставляет данные.
3. `useContext(Context)` (или `<Context.Consumer>`): потребитель читает данные в любой точке вложенного дерева.

**Когда использовать:**
- Глобальные данные приложения: текущая цветовая тема (светлая/темная), язык локализации интерфейса, авторизованный пользователь, конфигурация прав доступа.

### 10. Какие преимущества предоставляют кастомные хуки и как создавать собственные хуки?

**Кастомный хук** — это функция JavaScript, имя которой начинается с приставки `use` (например, `useFetch`, `useLocalStorage`), и которая внутри может вызывать другие встроенные хуки React.

**Преимущества:**
1. **Повторное использование логики с состоянием**: возможность вынести общую бизнес-логику (запросы к серверу, таймеры, сохранение в хранилище, слушатели событий) из компонентов в отдельные переиспользуемые модули.
2. **Чистота и читаемость UI-компонентов**: компонент фокусируется исключительно на верстке и отображении, а вся сложная логика скрыта внутри хука.
3. **Изолированность состояния**: каждый вызов кастомного хука создает полностью независимое изолированное состояние.
