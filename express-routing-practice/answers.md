### 1. В чем преимущества использования Express.js по сравнению с чистым Node.js для создания серверов?

| Критерий | Чистый Node.js (`http`) | Express.js |
| :--- | :--- | :--- |
| Маршрутизация | Ручной парсинг URL через `url.parse()` и громоздкие цепочки `if/else` или `switch`. | Встроенная декларативная маршрутизация с поддержкой шаблонов путей и регулярных выражений (`app.get`, `app.post`). |
| Чтение тела запроса | Требуется вручную подписываться на потоковые события `req.on('data')` и `req.on('end')`. | Готовые middleware, например `express.json()` и `express.urlencoded()`, доступ к телу через `req.body`. |
| Middleware-архитектура | Требует собственной реализации пайплайна и передачи контекста. | Стандартизированная конвейерная модель с поддержкой сотен сторонних пакетов (`cors`, `helmet`, `morgan`). |
| Отправка ответов | Ручная установка заголовков `writeHead` и сериализация в `res.end(JSON.stringify(...))`. | Удобные вспомогательные методы: `res.json()`, `res.status()`, `res.send()`, `res.sendFile()`. |

### 2. Что такое middleware в Express.js и каков порядок их выполнения?
**Middleware** (промежуточное ПО) — это функции, имеющие доступ к объекту запроса (`req`), объекту ответа (`res`) и следующей функции middleware в цикле «запрос-ответ» (`next`).

Порядок выполнения:
1. Middleware выполняются **строго последовательно** в том порядке, в котором они были подключены через `app.use()` или в определении маршрута.
2. Каждый middleware обязан либо завершить цикл «запрос-ответ» (вызвав `res.send()`, `res.json()`), либо передать управление дальше вызовом `next()`.
3. Если в `next()` передается аргумент (например, `next(err)`), Express прерывает стандартную цепочку и переходит к обработчикам ошибок.

```javascript
app.use((req, res, next) => {
  console.log('1. Первое действие');
  next();
});

app.use((req, res, next) => {
  console.log('2. Второе действие');
  next();
});
```

### 3. Как организовать модульную структуру роутеров в Express приложении?
Для разделения маршрутов по сущностям используется класс `express.Router()`:

1. В отдельных файлах (папка `routes/`) создаются изолированные роутеры:
   ```javascript
   // routes/users.js
   const express = require('express');
   const router = express.Router();

   router.get('/', (req, res) => res.json({ users: [] }));
   router.get('/:id', (req, res) => res.json({ user: req.params.id }));

   module.exports = router;
   ```
2. В основном файле `app.js` роутеры монтируются к базовым путям:
   ```javascript
   const usersRouter = require('./routes/users');
   const productsRouter = require('./routes/products');

   app.use('/api/users', usersRouter);
   app.use('/api/products', productsRouter);
   ```

### 4. Какие методы роутинга поддерживает Express.js и для чего они используются?
Express поддерживает все стандартные методы HTTP через функции вида `app.METHOD(path, handler)`:
- `app.get()` — чтение данных без изменения состояния сервера.
- `app.post()` — создание нового ресурса или отправка чувствительных данных.
- `app.put()` — полное замещение существующего ресурса переданным объектом.
- `app.patch()` — частичное обновление указанных полей ресурса.
- `app.delete()` — удаление ресурса по идентификатору.
- `app.options()` — обработка предварительных CORS-запросов.
- `app.all()` — перехват запросов с любым HTTP-методом по указанному пути (удобно для авторизации или валидации заголовков).

### 5. Как обрабатывать параметры URL и query-параметры в Express?

1. **Параметры пути (Path parameters)**: определяются через двоеточие в шаблоне маршрута и доступны в объекте `req.params`:
   ```javascript
   // Маршрут: /api/users/:id
   // Запрос:  GET /api/users/42
   const { id } = req.params; // '42' (строковый тип)
   ```
2. **Параметры строки запроса (Query parameters)**: передаются после знака `?` в URL, автоматически парсятся Express и доступны в `req.query`:
   ```javascript
   // Запрос: GET /api/products?category=electronics&inStock=true
   const { category, inStock } = req.query; // category = 'electronics', inStock = 'true'
   ```

### 6. В чем разница между `app.use()` и `app.METHOD()`?

| Критерий | `app.use()` | `app.METHOD()` (например, `app.get()`, `app.post()`) |
| :--- | :--- | :--- |
| Метод HTTP | Реагирует на **любой** HTTP-метод (`GET`, `POST`, `PUT`, `DELETE` и др.). | Реагирует **только на указанный конкретный метод**. |
| Сопоставление пути | Префиксное сопоставление: `app.use('/api')` сработает для `/api`, `/api/users`, `/api/users/1/details`. | Точное совпадение шаблона маршрута. |
| Основное назначение | Подключение middleware общего назначения (логирование, парсинг JSON, безопасность, монтирование дочерних роутеров). | Реализация конкретных конечных точек (эндпоинтов) API. |

### 7. Как организовать централизованную обработку ошибок в Express приложении?
Централизованный обработчик ошибок определяется с **четырьмя аргументами** `(err, req, res, next)` в самом конце файла `app.js` (после объявления всех маршрутов):

```javascript
// Генерация ошибки в маршруте:
app.get('/api/data', (req, res, next) => {
  try {
    throw new Error('База данных временно недоступна');
  } catch (err) {
    next(err); // передача ошибки обработчику
  }
});

// Централизованный middleware-обработчик:
app.use((err, req, res, next) => {
  console.error('Стек ошибки:', err.stack);
  
  const statusCode = err.status || 500;
  res.status(statusCode).json({
    error: err.name || 'InternalServerError',
    message: err.message || 'Внутренняя ошибка сервера'
  });
});
```

### 8. Что такое `router.param()` и для чего он используется?
`router.param(name, callback)` — это специальный middleware-обработчик, который автоматически триггерится при наличии указанного именованного параметра в маршруте.

Назначение:
1. Предварительная валидация формата параметра (например, проверка, что `id` является положительным числом, с немедленным возвратом ошибки 400).
2. Загрузка сущности из базы данных и сохранение в объекте `req` (например, `req.user = loadedUser`), исключая дублирование кода поиска в `GET`, `PUT` и `DELETE` маршрутах.

```javascript
router.param('id', (req, res, next, id) => {
  const parsedId = parseInt(id, 10);
  if (isNaN(parsedId)) {
    return res.status(400).json({ error: 'Неверный формат ID' });
  }
  req.userId = parsedId;
  next();
});
```
