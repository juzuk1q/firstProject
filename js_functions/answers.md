## 1. В чем разница между Function Declaration и Function Expression в контексте hoisting (поднятия)?
Function Declaration (объявление функции):
  ```javascript
  function calculateTotal(a, b) {
      return a + b;
  }
  ```
  Поднимается (hoisted) на этапе компиляции/создания контекста выполнения **полностью вместе с телом функции**. Это позволяет вызывать функцию в коде выше места её фактического расположения:
  ```javascript
  greet(); // Работает корректно: "Привет!"
  function greet() { console.log("Привет!"); }
  ```

Function Expression (функциональное выражение):
  ```javascript
  const calculateTotal = function(a, b) {
      return a + b;
  };
  ```
  Здесь функция создается как часть выражения присваивания переменной. Поднимается только само объявление переменной:
  * Если переменная объявлена через `var`, она инициализируется значением `undefined`. Попытка вызова до строки инициализации приведет к ошибке: `TypeError: calculateTotal is not a function`.
  * Если переменная объявлена через `let` или `const`, она находится во «временной мертвой зоне» (Temporal Dead Zone, TDZ) до момента выполнения строки с присваиванием. Попытка вызова до объявления приведет к ошибке: `ReferenceError: Cannot access 'calculateTotal' before initialization`.

## 2. Как работают rest parameters (`...args`) и в чем их отличие от `arguments` object?
Rest parameters (`...args` - остаточные параметры):**
  Позволяют собрать неограниченное число аргументов в настоящий массив JavaScript (`Array.isArray(args) === true`).
  ```javascript
  function sumAll(...numbers) {
      return numbers.reduce((acc, n) => acc + n, 0); // Доступны все методы Array
  }
  ```
Ключевые отличия от `arguments`:**
  Тип данных: `...args` - это полноценный экземпляр `Array`, имеющий методы `.map()`, `.filter()`, `.reduce()`, `.slice()`. Объект `arguments` - это устаревший псевдомассив (array-like object), имеющий лишь свойство `length` и индексацию элементов. Для работы с ним требовалось явное преобразование (`Array.from(arguments)`).
  Стрелочные функции:** У стрелочных функций объекта `arguments` нет вообще (он берется из внешней обычной функции при ее наличии), тогда как `...args` поддерживается во всех типах функций.
  Гибкость позиционирования: `...args` собирает только оставшиеся аргументы (например, `function(prefix, ...items)`), в то время как `arguments` содержит абсолютно все переданные аргументы.
  Читаемость: Rest parameters явно декларируются в сигнатуре функции, документируя намерение разработчика.

## 3. Что такое замыкание (closure) и как оно связано с лексической областью видимости?
Замыкание (Closure) - это способность функции сохранять доступ к переменным из своей внешней области видимости (лексического окружения, `Lexical Environment`) даже после того, как внешняя функция завершила свое выполнение и вернула управление. В JavaScript каждая функция при создании получает скрытую ссылку `[[Environment]]` на то окружение, где она была создана.
Связь с лексической областью видимости:
  Лексическая область видимости (Lexical Scope) означает, что доступ к переменным определяется **местом объявления** функции в коде, а не местом её фактического вызова в рантайме.
Практический пример из работы:
  В функции `secretMessage(password, message)` переменные `password` и `message` остаются доступны только внутренней возвращаемой функции проверки. Внешний код не может напрямую изменить или прочитать секретное сообщение в обход проверки пароля, что реализует строгую инкапсуляцию приватного состояния.

## 4. Когда следует использовать рекурсию, а когда итерацию? Какие преимущества и недостатки у каждого подхода?

| Критерий | Рекурсия | Итерация (циклы `for`, `while`) |
| :--- | :--- | :--- |
| **Когда использовать** | Обработка древовидных и графовых структур данных (DOM-дерево, вложенные JSON-объекты, файловые системы), алгоритмы «разделяй и властвуй» (QuickSort, MergeSort), композиция функций (`compose`). | Линейные массивы, фиксированные счетчики, критичные к производительности участки кода, потоковая обработка. |
| **Преимущества** | Декларативный, лаконичный и математически элегантный код; естественное соответствие самоподобным структурам данных. | Максимальная скорость работы, детерминированное потребление памяти $O(1)$, отсутствие накладных расходов на вызов функций. |
| **Недостатки** | Расход оперативной памяти под стек вызовов ($O(n)$ фреймов); риск переполнения стека (`RangeError: Maximum call stack size exceeded`), так как движки V8/SpiderMonkey не имеют гарантированной оптимизации хвостовой рекурсии (TCO). | Более громоздкий императивный код при обходе ветвящихся структур с переменным уровнем вложенности (требует ручного стека). |

## 5. Как работают функции высшего порядка и какие встроенные методы массивов являются таковыми?
Функция высшего порядка (Higher-Order Function, HOF)** - это функция, которая удовлетворяет хотя бы одному из условий:
  Принимает одну или несколько функций в качестве аргументов (callbacks).
  Возвращает другую функцию в качестве результата своего выполнения.
Принцип работы: HOF абстрагируют логику управления (циклы, проверки, задержки), позволяя передавать конкретные действия параметрами.
Встроенные методы массивов:
  * `Array.prototype.map(callback)` - трансформация каждого элемента в новый массив.
  * `Array.prototype.filter(callback)` - отбор элементов по предикату-условию.
  * `Array.prototype.reduce(callback, initialValue)` / `reduceRight` - свертка массива к аккумулятору.
  * `Array.prototype.forEach(callback)` - выполнение побочного действия для каждого элемента.
  * `Array.prototype.some(callback)` / `every(callback)` - кванторы существования и всеобщности.
  * `Array.prototype.find(callback)` / `findIndex(callback)` - поиск элемента или его индекса.
  * `Array.prototype.sort(compareFn)` - сортировка на основе пользовательского компаратора.
  * `Array.prototype.flatMap(callback)` - отображение с последующим уплощением на 1 уровень.

## 6. Что такое каррирование и какие практические преимущества оно дает?
Каррирование (Currying) - это метод трансформации функции от нескольких аргументов $f(a, b, c)$ в цепочку унарных функций (функций от одного аргумента): $f(a)(b)(c)$.
**Практические преимущества:**
  Частичное применение (Partial Application):** возможность зафиксировать часть аргументов (например, коэффициент налога, базовый URL API, логгер определенного уровня) и получить специализированную функцию:
     ```javascript
     const log = curry((level, time, msg) => `[${level}] ${time}: ${msg}`);
    const logError = log('ERROR')(new Date().toLocaleTimeString());
     logError('База данных недоступна');
     ```
  Легкая композиция: унарные функции идеально объединяются через `compose` или `pipe`, передавая результат одной функции на вход следующей.
  Переиспользуемость и чистота: функции становятся более модульными и независимыми от контекста окружения.

## 7. Как работает мемоизация и в каких случаях ее использование наиболее эффективно?
Принцип работы:
  Мемоизация (Memoization) - это паттерн кэширования результатов выполнения функции. На основе входных аргументов формируется уникальный ключ (например, через `JSON.stringify(args)`). Перед запуском алгоритма функция проверяет наличие ключа в кэше (`Map`). Если ключ найден, возвращается сохраненный результат; если нет - выполняется вычисление, сохраняется в кэш и возвращается пользователю.
Когда наиболее эффективно:
  * Функция является чистой (pure function) - детерминированной и не имеющей побочных эффектов.
  * Функция производит ресурсоемкие вычисления (рекурсивные расчеты чисел Фибоначчи, факториалов, графовых путей, тяжелый парсинг текста).
  * Набор входных аргументов относительно невелик и часто повторяется при работе программы.
Когда неэффективно:
  * Для нечистых функций, зависящих от внешнего мира (сетевые запросы, `Math.random()`, текущее время).
  * Если аргументы каждый раз уникальны - накладные расходы на сериализацию и память кэша только замедлят работу приложения.

## 8. В чем разница между `debounce` и `throttle` и когда следует использовать каждый подход?

| Характеристика | Debounce (устранение дребезга) | Throttle (регулирование частоты) |
| :--- | :--- | :--- |
| Суть поведения | «Заставляет» функцию сработать только тогда, когда поток вызовов прекратился на заданное время $T$. Каждый новый вызов сбрасывает таймер. | Гарантирует выполнение функции *не чаще одного раза* за фиксированный интервал времени $T$, пропуская избыточные срабатывания. |
| Аналогия из жизни | Закрытие дверей лифта: двери закроются только спустя 5 секунд после того, как в лифт зашел последний человек. | Бутылочное горлышко или стробоскоп: пропускает одну порцию строго раз в заданное время, независимо от напора. |
| Типичные сценарии | 1. Валидация формы на лету при наборе текста.<br>2. Автокомплит и живой поиск (поисковые подсказки).<br>3. Автосохранение черновика статьи после завершения печати. | 1. Обработка событий скролла (`window.addEventListener('scroll')`).<br>2. Перетаскивание элементов (drag-and-drop / `mousemove`).<br>3. Перерасчет верстки при ресайзе окна (`resize`). |

## 9. Как функции-генераторы (`function*`) отличаются от обычных функций?
Модель выполнения:
   * Обычная функция выполняется непрерывно по модели «run-to-completion» - от начала до конца или первого `return`.
   * Функция-генератор может приостанавливать свое выполнение с помощью оператора `yield` и возобновлять его позже с того же места, сохраняя все локальные переменные.
Возвращаемое значение:
   * Обычная функция возвращает вычисленное значение (или `undefined`).
   * Генератор возвращает объект-итератор (`Generator`), соответствующий протоколу итерации ES6 (`Iterable / Iterator protocol`).
Метод `.next()`:
   * Управление генератором происходит через вызовы `.next()`, возвращающие объект вида `{ value: Any, done: Boolean }`.
Двусторонняя коммуникация:
   * Генератор может не только отдавать данные во внешний код (`yield value`), но и принимать новые значения извне в момент возобновления (`const input = yield;` -> `gen.next("данные")`).
Ленивые вычисления (Lazy Evaluation):
   * Генераторы позволяют создавать бесконечные последовательности данных (например, бесконечный генератор простых чисел или ID), вычисляя значения строго по запросу без опасности исчерпания памяти.

## 10. Какие принципы функционального программирования вы применили в ходе работы и в чем их benefits?
Чистые функции (Pure Functions):
   * Функции `sum`, `compose`, `curry`, `myMap`, `myFilter` детерминированы: при одинаковых входных аргументах они возвращают одинаковый результат и не влияют на внешнюю среду (no side effects).
   * Преимущество: предельная предсказуемость кода, отсутствие скрытых багов и максимальная легкость покрытия юнит-тестами.
Иммутабельность (Immutability):
   * В реализациях `myMap`, `myFilter`, `myReduce` исходный массив никогда не модифицируется (не мутирует); всегда возвращается новая коллекция данных.
   * Преимущество: предотвращение трудноуловимых багов, связанных с неожиданным изменением данных другими участками программы.
Функции первого класса (First-Class Functions) и HOF:
   * В JavaScript функции являются объектами первого класса: они передаются как аргументы, сохраняются в переменные и возвращаются из других функций (`curry`, `debounce`, `throttle`, `createValidator`, `secretMessage`).
   * Преимущество: высочайший уровень абстракции и повторного использования кода.
Композиция функций (Function Composition):
   * Объединение нескольких независимых простых функций в единый конвейер трансформации данных (`compose(h, g, f)(x)`).
   * Преимущество: отказ от глубокой вложенности вызовов и замена процедурного спагетти-кода на ясный декларативный поток данных.
