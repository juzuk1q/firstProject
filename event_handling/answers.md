## 1. В чем разница между `event.preventDefault()` и `event.stopPropagation()`? В каких ситуациях используется каждый метод?

`event.preventDefault()`:
  * Назначение: отменяет стандартное действие браузера, предусмотренное спецификацией для данного типа события по умолчанию.
  * Влияние на всплытие: не останавливает распространение события вверх или вниз по DOM-дереву (событие продолжает всплывать к родителям).
  * Когда используется:
    * Отмена перезагрузки страницы при отправке HTML-формы (`form.addEventListener('submit', (e) => e.preventDefault())`).
    * Блокировка перехода по URL при клике на тег `<a href="...">`.
    * Перехват глобальных горячих клавиш клавиатуры (например, предотвращение открытия диалога сохранения страницы браузера при `Ctrl + S`).
    * Предотвращение открытия стандартного контекстного меню (`contextmenu`).

`event.stopPropagation()`:
  * Назначение: останавливает распространение события по DOM-дереву (прекращает фазу всплытия или погружения).
  * Влияние на стандартное поведение: никак не отменяет стандартное действие самого элемента.
  * Когда используется:
    * В модальных окнах: предотвращение закрытия модалки при клике внутри её контента (чтобы клик не всплывал на оверлей-подложку).
    * При вложенных интерактивных элементах (например, кнопка «Удалить» или чекбокс внутри кликабельной строки таблицы).
*Примечание:* если требуется остановить не только всплытие к родителям, но и работу всех остальных слушателей на текущем узле, используется `event.stopImmediatePropagation()`.

## 2. Как работает делегирование событий и какие преимущества оно дает по сравнению с назначением обработчиков на отдельные элементы?
Принцип работы:
  Делегирование событий опирается на механизм всплытия событий (bubbling). Любое событие, произошедшее на самом глубоко вложенном элементе (цели `event.target`), автоматически поднимается вверх по родительской цепочке.
  Вместо назначения десятков или сотен отдельных обработчиков на каждый дочерний элемент мы назначаем один общий обработчик на их родительский контейнер:
  ```javascript
  const itemList = document.getElementById('item-list');
  itemList.addEventListener('click', (event) => {
      // Ищем ближайший элемент .item или кнопку внутри
      const deleteBtn = event.target.closest('.delete');
      if (deleteBtn) {
          deleteBtn.closest('.item').remove();
          return;
      }
      const item = event.target.closest('.item');
      if (item) {
          item.classList.toggle('selected');
      }
  });
  ```
Преимущества:
- Автоматическая поддержка динамических элементов: любые новые элементы, добавленные в список позже через `appendChild` или AJAX, сразу будут обрабатываться без необходимости прикреплять слушатели заново.
- Колоссальная экономия оперативной памяти: в памяти существует ровно один экземпляр функции-обработчика вместо $N$ штук.
- Отсутствие утечек памяти при удалении элементов: при удалении узлов из DOM не нужно явно удалять с них слушатели событий.

## 3. Какие фазы жизненного цикла события существуют в JavaScript (capturing, target, bubbling) и как они влияют на порядок выполнения обработчиков?
При возникновении события в DOM оно проходит три последовательные фазы:
1. Фаза погружения / перехвата (Capturing phase):
   * Событие распространяется от самого верхнего узла окна `window` вниз через `document`, `<html>`, `<body>` и цепочку предков к родительскому элементу целевого узла.
   * Обработчики, зарегистрированные с флагом `{ capture: true }` (или третьим аргументом `true`), выполняются именно на этой фазе.
2. Фаза цели (Target phase):
   * Событие достигает непосредственно того узла, на котором оно было инициировано (`event.target`).
   * Обработчики, назначенные на саму цель, срабатывают независимо от направления.
3. Фаза всплытия (Bubbling phase):
   * Событие начинает подниматься обратно вверх от целевого узла через всех предков до `window`.
   * По умолчанию метод `element.addEventListener('click', handler)` регистрирует слушатели именно для фазы всплытия (`capture: false`).
Порядок выполнения: сначала сверху вниз отрабатывают все слушатели захвата (capturing), затем обработчики на целевом элементе, и только затем снизу вверх выполняются всплывающие обработчики (bubbling). Подавляющее большинство практических задач решается на фазе всплытия.

## 4. В чем разница между `event.target` и `event.currentTarget`? Когда следует использовать каждый из них?

| Свойство | Что представляет собой | Мутирует ли при всплытии |
| :--- | :--- | :--- |
| `event.target` | Исходный целевой элемент, на котором непосредственно произошло событие (по которому физически кликнули мышью или ввели текст). | Нет, сохраняет ссылку на исходного инициатора на всех фазах. |
| `event.currentTarget` (эквивалентен `this` в обычных функциях) | Текущий элемент, чей обработчик события сейчас выполняется (к которому привязан `addEventListener`). | Меняется по мере продвижения события по цепочке предков. |
Когда что использовать:
  * `event.target` используется при делегировании событий, когда родителю нужно определить, по какой именно внутренней кнопке, иконке или ссылке кликнул пользователь (`event.target.closest('.delete')`).
  * `event.currentTarget` используется, когда нужно обратиться к свойствам или стилям именно того элемента, на котором висит обработчик, независимо от того, насколько глубоко внутри кликнул пользователь (например, навесить класс анимации на саму кнопку, даже если клик пришелся на иконку `<span>` внутри неё).

## 5. Как создать и запустить кастомное событие? Какие параметры можно передать в конструктор CustomEvent?
* Создание и вызов:
  ```javascript
  const customEvent = new CustomEvent('customAction', {
      detail: { message: 'Привет от кастомного события!', id: 42 },
      bubbles: true,
      cancelable: true
  });
  document.dispatchEvent(customEvent);
  ```
* Параметры объекта инициализации (словарь параметров):
  1. `detail` - объект произвольных пользовательских данных любого типа (числа, строки, объекты, функции), передаваемых вместе с событием. Доступен в слушателе через `event.detail`.
  2. `bubbles` (по умолчанию `false`) - логический флаг, определяющий, будет ли событие всплывать вверх по DOM-дереву. Если установить `true`, событие можно перехватить на предках и в `document`.
  3. `cancelable` (по умолчанию `false`) - разрешает ли событие отмену через `event.preventDefault()`. Метод `element.dispatchEvent(event)` возвращает `false`, если событие отменяемое и кто-то вызвал `preventDefault()`.
  4. `composed` (по умолчанию `false`) - определяет, способно ли событие всплывать за пределы теневого DOM (Shadow DOM) в компонентной архитектуре (Web Components).

## 6. Что такое debounce и throttle? В каких практических ситуациях их применение наиболее эффективно?
Оба паттерна предназначены для оптимизации и контроля частоты вызовов функций:
* Debounce (устранение дребезга):
  * Задерживает вызов функции до тех пор, пока с момента *последнего* вызова не пройдет заданный интервал $T$. Любой новый вызов в период ожидания сбрасывает таймер.
  * Где применяется:
    * Живой поиск и автокомплит: отправка AJAX-запроса только после того, как пользователь закончил ввод текста.
    * Валидация полей ввода по мере печати.
    * Сохранение черновика текста в LocalStorage после паузы в наборе.

* Throttle (регулирование пропускной способности):
  * Гарантирует выполнение функции не чаще одного раза за фиксированный интервал времени $T$, равномерно распределяя вызовы.
  * Где применяется:
    * Обработка событий скролла (`window.addEventListener('scroll')`) - отслеживание бесконечной прокрутки или положения хедера.
    * Изменение размеров окна браузера (`resize`).
    * Отслеживание координат перемещения курсора мыши (`mousemove`, драг-энд-дроп).
    * Ограничение частоты нажатий на кнопку выстрела в браузерных играх или защита от спам-кликов («Double Submit Prevention»).

## 7. Какие методы существуют для удаления обработчиков событий и почему важно удалять ненужные обработчики?
Методы удаления:
  1. `element.removeEventListener(type, handler, options)`:
     Для корректного удаления необходимо передать точную ссылку на ту же самую именованную функцию:
     ```javascript
     function onScroll() { ... }
     window.addEventListener('scroll', onScroll);
     window.removeEventListener('scroll', onScroll); // Успешно удален
     ```
     *Анонимную функцию (`() => {}`), переданную в `addEventListener`, удалить через `removeEventListener` невозможно.*
  2. Опция `{ once: true }`:
     Обработчик автоматически отписывается и удаляется сборщиком мусора сразу после своего первого выполнения.
  3. Использование `AbortController` (современный стандарт):
     ```javascript
     const controller = new AbortController();
     window.addEventListener('resize', handler, { signal: controller.signal });
     // В нужный момент (например, при демонтировании компонента):
     controller.abort(); // Удаляет все связанные слушатели одной командой
     ```
Почему это критически важно:
  Неудаленные обработчики держат через замыкания ссылки на удаленные DOM-узлы и контексты выполнения, что приводит к утечкам оперативной памяти (Memory Leaks), деградации производительности страницы и фантомным багам повторного выполнения логики.

## 8. Как обрабатывать ошибки загрузки ресурсов (изображений, скриптов) и какие события для этого используются?
* События:
  * `load` - генерируется при успешной загрузке и разборе ресурса.
  * `error` - генерируется, если ресурс не удалось загрузить (ошибка сети, статус 404/500, блокировка CORS, битый файл).
* Особенности поведения:
  * События `load` и `error` на ресурсах (`<img>`, `<script>`, `<link>`) не всплывают (не bubbling). Их нельзя поймать на фазе всплытия через делегирование на контейнере!
  * Для их отслеживания либо слушатель вешается прямо на целевой элемент:
    ```javascript
    const img = document.createElement('img');
    img.addEventListener('load', () => console.log('Успех'));
    img.addEventListener('error', () => {
        container.className = 'error';
        console.error('Ошибка загрузки');
    });
    img.src = url; // Присваивать src строго ПОСЛЕ навешивания слушателей!
    ```
  * Либо используется перехват на фазе погружения (capturing) на уровне `window`:
    ```javascript
    window.addEventListener('error', (event) => {
        if (event.target.tagName === 'IMG') {
            console.warn('Сбой загрузки картинки:', event.target.src);
        }
    }, true); // true = фаза перехвата (capture)
    ```

## 9. В чем разница между `addEventListener` и прямым назначением обработчиков через `onclick`, `onkeydown` и т.д.?

| Характеристика | Свойство `element.onclick = fn` | Метод `element.addEventListener('click', fn)` |
| :--- | :--- | :--- |
| Количество обработчиков | Только один: повторное присвоение `element.onclick = fn2` перезаписывает предыдущий обработчик. | Неограниченно: можно добавить множество независимых слушателей на одно и то же событие. |
| Управление фазами | Работает только на фазе всплытия (bubbling). | Поддерживает обе фазы (погружение `{ capture: true }` и всплытие). |
| Расширенные опции | Не поддерживает параметры. | Поддерживает объект опций: `{ once: true }`, `{ passive: true }`, `{ signal: AbortSignal }`. |
| Кастомные события | Не поддерживает (`element.oncustomAction` не существует). | Позволяет слушать любые кастомные события (`CustomEvent`). |
| Удаление | `element.onclick = null;` | `element.removeEventListener('click', fn)` или через `AbortController`. |

## 10. Как оптимизировать производительность при работе с большим количеством событий? Какие лучшие практики существуют?
1. Делегирование событий (Event Delegation):
   Один глобальный слушатель на родительском контейнере вместо назначения слушателей на сотни или тысячи карточек/строк списка.
2. Использование пассивных слушателей (`passive: true`):
   Для высоконагруженных событий прокрутки и тач-жестов (`scroll`, `touchstart`, `touchmove`):
   ```javascript
   window.addEventListener('scroll', onScroll, { passive: true });
   ```
   Флаг `passive: true` гарантирует браузеру, что обработчик никогда не вызовет `preventDefault()`, позволяя браузеру скроллить страницу в отдельном потоке без задержек и фризов.
3. Применение паттернов Debounce и Throttle:
   Ограничение частоты выполнения тяжелых обработчиков (`resize`, `scroll`, живой ввод текста), предотвращающее перегрузку процессора.
4. Своевременная отписка от событий (Cleanup):
   Удаление слушателей при уничтожении элементов или модальных окон для предотвращения утечек памяти и холостых вызовов.
5. Использование `requestAnimationFrame`:
   Если обработчик события изменяет визуальное представление (стили, координаты), выполнять эти изменения внутри коллбэка `requestAnimationFrame`, синхронизируя перерисовку с разверткой монитора и избегая лишних принудительных перерасчетов макета (Forced Synchronous Layout).
