1. Какое основное свойство CSS включает Flexbox и что происходит с дочерними элементами после его применения?
Flexbox включается свойством display: flex, применённым к родительскому элементу (flex-контейнеру). После этого все непосредственные дочерние элементы автоматически становятся flex-элементами: они выстраиваются в ряд вдоль главной оси (горизонтально по умолчанию), теряют своё поведение по умолчанию (например, float перестаёт работать), а их размеры и расположение начинают управляться свойствами flex-grow, flex-shrink, flex-basis, justify-content, align-items и другими flex-свойствами.

2. В чём разница между justify-content и align-items? Приведите примеры использования каждого.
justify-content управляет выравниванием элементов вдоль главной оси, а align-items - вдоль поперечной оси. При flex-direction: row главная ось горизонтальна, поэтому justify-content отвечает за горизонтальное расположение (например, justify-content: space-between равномерно распределяет карточки в футере), а align-items - за вертикальное (например, align-items: center в .header вертикально центрирует заголовок внутри блока высотой 100px).

3. Что делает свойство flex-direction и какие значения может принимать? Как оно влияет на основную ось?
flex-direction задаёт направление главной оси и порядок расположения flex-элементов внутри контейнера. Возможные значения: row, row-reverse, column, column-reverse. При значении row/row-reverse главная ось горизонтальна, а при column/column-reverse - вертикальна; соответственно меняется и то, какие свойства отвечают за горизонтальное, а какие - за вертикальное выравнивание. Именно поэтому в медиа-запросе .main { flex-direction: column; } разворачивает сайдбар, контент и боковую панель в колонку на мобильных экранах.

4. Объясните значение трёх свойств в сокращённой записи flex: 1. Что означают flex-grow, flex-shrink и flex-basis?
Запись flex: 1 - это сокращение для flex-grow: 1; flex-shrink: 1; flex-basis: 0%. flex-grow определяет, насколько элемент может увеличиваться относительно других элементов, когда в контейнере есть свободное место (например, .card { flex: 1; } заставляет все карточки растягиваться и занимать равную ширину). flex-shrink определяет, насколько элемент может сжиматься, если места не хватает. flex-basis задаёт базовый размер элемента до распределения свободного пространства - например, .sidebar { flex: 0 0 250px; } означает, что боковая панель не растягивается (flex-grow: 0), не сжимается (flex-shrink: 0) и всегда имеет базовую ширину 250px.

5. Как работает свойство flex-wrap и в каких случаях его следует использовать?
По умолчанию flex-контейнер пытается разместить все элементы в одну линию (flex-wrap: nowrap), сжимая их при нехватке места. Свойство flex-wrap: wrap разрешает элементам переноситься на новую строку, если они не помещаются в текущую ширину контейнера - как в .content { flex-wrap: wrap; }, где карточки при уменьшении ширины экрана начинают переноситься на следующую строку вместо сжатия. Это полезно, когда заранее неизвестно количество элементов или ширина экрана может сильно меняться, и нужно избежать чрезмерного сжатия содержимого.

6. Чем отличается align-content от align-items и когда применяется каждое из этих свойств?
align-items выравнивает отдельные flex-элементы по поперечной оси внутри одной строки. align-content управляет распределением самих строк (когда их несколько, то есть при flex-wrap: wrap и наличии свободного места по поперечной оси) относительно всего контейнера - например, задаёт промежутки между строками карточек или их выравнивание сверху/снизу/по центру, если строк с элементами несколько. Если у контейнера всего одна строка элементов, align-content не оказывает видимого эффекта, и работает только align-items.

7. Как свойство order влияет на отображение элементов и в каких практических ситуациях оно может быть полезно?
Свойство order задаёт визуальный порядок отображения flex-элемента независимо от его порядка в HTML-разметке: элементы с меньшим значением order отображаются раньше (по умолчанию order: 0 у всех элементов). В задании 5.1 .card:nth-child(2) { order: 1; } и .card:nth-child(1) { order: 2; } меняют местами первую и вторую карточки визуально, хотя в HTML их порядок не изменился. Практически это полезно для адаптивного дизайна - например, чтобы на мобильной версии сначала показать самый важный блок контента, хотя в разметке он идёт не первым.

8. Что такое «осевая линия» (main axis) и поперечная ось (cross axis) в Flexbox и как они связаны с flex-direction?
Главная ось (main axis) - это направление, вдоль которого flex-контейнер располагает свои элементы; поперечная ось (cross axis) всегда перпендикулярна главной. Направление главной оси задаётся свойством flex-direction: при row/row-reverse главная ось горизонтальна, а поперечная - вертикальна; при column/column-reverse, наоборот, главная ось вертикальна, а поперечная - горизонтальна. От того, какая ось является главной, зависит, какое из свойств (justify-content или align-items/align-content) отвечает за то или иное направление выравнивания.

9. Как создать адаптивный макет с помощью Flexbox без использования медиа-запросов? Приведите пример.
Можно использовать flex-wrap: wrap в сочетании с гибким flex-basis/flex-grow, чтобы элементы сами переносились на новую строку и меняли ширину по мере уменьшения экрана, без явных точек перелома. Например: .card { flex: 1 1 200px; } внутри контейнера с display: flex; flex-wrap: wrap; - каждая карточка стремится занять не менее 200px, но при этом растягивается (flex-grow: 1), заполняя доступное пространство, а при нехватке места автоматически переносится на следующую строку - макет подстраивается под ширину экрана без единого @media.

10. Какие преимущества даёт использование gap вместо margins для создания промежутков между flex-элементами?
gap задаёт единый промежуток между элементами на уровне контейнера (как в .content { gap: 1rem; }), не создавая отступа снаружи от крайних элементов - в отличие от margin, который пришлось бы дополнительно обнулять у первого/последнего элемента, чтобы не съезжал общий контейнер. gap также не требует использования псевдоклассов вроде :not(:last-child) для избежания «лишнего» последнего отступа, корректно работает при переносе строк (flex-wrap: wrap), создавая одинаковые отступы и между строками, и не влияет на итоговые расчёты flex-basis/процентных ширин элементов, как это может делать margin.
