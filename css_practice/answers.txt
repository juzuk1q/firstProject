1. ID уникален на странице (#site-title может встретиться только один раз), поэтому селектор по ID имеет высокую специфичность (1,0,0) и не предназначен для переиспользования - он привязан к конкретному элементу. 
   Класс (.subtitle) можно навесить на сколько угодно элементов, специфичность ниже (0,1,0), поэтому классы - основной инструмент переиспользуемых стилей, а ID лучше оставить для якорных ссылок и JS-хуков, а не для стилизации.

2. При конфликте правил браузer решает, какое применить, по цепочке приоритетов: 
   1) !important - побеждает всегда, кроме конфликта с другим !important (тогда решает специфичность/порядок); 
   2) специфичность селектора - чем она выше, тем правило важнее; 
   3) при одинаковой специфичности - побеждает правило, объявленное позже в исходном коде (или подключённое позже как файл). 
   
   Наследование и стили браузера по умолчанию имеют самый низкий приоритет.

3. ul li.important --> два тега + один класс --> специфичность (0,1,2)
   #site-title --> один id --> специфичность (1,0,0)
   .content > .featured-post --> два класса, комбинатор > не считается --> специфичность (0,2,0)

   По убыванию приоритета: #site-title (1,0,0) > .content > .featured-post (0,2,0) > ul li.important (0,1,2).

4. Наследуются (в основном текстовые/типографические свойства):
      -  color
      -  font-family
      -  line-height
   Не наследуются (в основном свойства блочной модели и оформления):
      -  border
      -  padding / margin
      -  background-color

5. .content > article выбирает только те <article>, которые являются прямыми детьми .content - вложенные глубже (например, статья внутри дополнительного <section>) под это правило не попадут. .post p - селектор потомков - выбирает <p> на любом уровне вложенности внутри .post, хоть через десять промежуточных тегов. Дочерний селектор точнее и предсказуемее, но более хрупкий при изменении разметки.

6. :hover применяет стиль, пока курсор находится над элементом - используется для интерактивной обратной связи: подсветка пункта меню, кнопки, строки списка. 
   :nth-child() выбирает элементы по их позиции среди соседей (например, :nth-child(odd)) - незаменим для «зебры» в таблицах и списках, чередующихся цветов карточек, без добавления лишних классов в разметку.

7. !important заставляет правило побеждать в каскаде независимо от специфичности селектора, перекрывая почти всё, кроме другого !important с более высоким приоритетом. Опасность в том, что он ломает предсказуемость каскада: следующему разработчику (или вам самим через полгода) придётся переопределять уже не через нормальную специфичность, а искать, где стоит !important, и добавлять свой - код быстро превращается в «войну важностей». Использовать стоит только как точечное, осознанное исключение (например, для утилитарных классов или переопределения стилей сторонней библиотеки).

8. Эти псевдоэлементы вставляют «виртуальный» узел до или после содержимого элемента, не добавляя ничего в HTML-разметку. В свойстве content можно указать текст, символ/эмодзи (как декоративная иконка перед карточкой), пустую строку (часто используется вместе с display и позиционированием для декоративных линий и фигур) или значение атрибута через attr(). Они не должны нести значимый для смысла страницы текст - это чисто визуальное дополнение, screenreader его либо игнорируют, либо озвучивают непредсказуемо.

9. Если специфичность двух конфликтующих селекторов равна, побеждает то правило, которое находится ниже по тексту (или в файле, подключённом позже). Поэтому порядок подключения CSS-файлов и порядок правил внутри файла имеют значение даже без разницы в специфичности.

10.Вкладка «Elements/Стили» показывает все правила, которые претендуют на выбранный элемент, с зачёркиванием тех, что были перебиты каскадом, - сразу видно, какое правило победило и почему. Там же можно на лету менять значения свойств и включать/выключать отдельные правила, чтобы проверить гипотезу, не трогая исходный файл. Вкладка «Computed» показывает итоговое, уже посчитанное значение каждого свойства с учётом наследования и каскада, а панель «Box model» наглядно показывает границы margin/border/padding/content.
