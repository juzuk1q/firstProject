1.	- Рабочая папка - файлы, с которыми пользователь непосредственно работает и изменяет их. Здесь находятся текущие версии файлов проекта.
	- Индекс - промежуточная область, куда добавляются изменения, подготовленные для следующего коммита. Для добавления используется команда git add.
	- Репозиторий - место, где Git хранит историю проекта: коммиты, версии файлов и информацию об изменениях. Из индекса изменения попадают сюда после выполнения git commit.

Главное отличие: рабочая папка содержит текущие изменения, индекс - изменения, выбранные для ближайшего коммита, а репозиторий - уже сохранённую историю проекта.

2.	git add - добавление изменения из рабочей папки в индекс, подготавливая их к коммиту.
	git commit - сохраняет подготовленные изменения из индекса в локальный репозиторийю
	git push - отправляет локальные коммиты в удалённый репозиторий.

3. Писать информативные сообщения к коммитам важно, чтобы по истории git было понятно, какие изменения были сделаны. Это упрощает поиск ошибок, откат изменений и работу в команде. Сообщения вроде "исправление" не дают полезной информации.

4.	git add file_name - добавляет в индекс только указанный файл.
	git add . - добавляет все изменения в текущей папке и её подпапках.
Первый способ удобен когда нужно выбрать конкретные изменения, второй - когда нужно подготовить сразу весь проект

5. git status показывает текущее состояние рабочей папки и индекса: изменённые, новые и удалённые файлы, а также файлы подготоввленные к коммиту. После git add файл переходит в список подготовленных, а после git commit изменений для коммита обычно уже нет.

6. Команда добавляет удалённый репозиторий по указанному URL. origin - стандартное имя, которое обычно дают основному удалённому репозиторию.

7. Он связывает локальную ветку main с удалённой веткой origin/main. После этого можно использовать просто git push и git pull без повторного указания репозитория и ветки.

8. Ветка по умолчанию - основная ветка проекта, с которой начинается работа. В современных версиях Git обычно используется main, но в некоторых старых или настроенных системах может быть master. Это важно потому что команды отправки и слияния изменений должны обращаться к правильной ветке.

9. Используется команда git log. Она показывает историю коммитов, включая хеш коммита, автора, дату и сообщение коммита.

10.Изменения не попадут в новый коммит. git commit сохранит только те изменения, которые уже были добавлены в индекс с помощью git add.
