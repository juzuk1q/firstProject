### 1. Что такое Node.js и в чем его преимущества для создания серверов?
**Node.js** — это кроссплатформенная среда выполнения JavaScript с открытым исходным кодом, построенная на базе движка V8 от Google. Она позволяет выполнять JavaScript-код вне браузера на стороне сервера.

| Преимущество | Описание |
| :--- | :--- |
| Неблокирующий I/O | Асинхронная модель ввода-вывода на основе Event Loop позволяет одному потоку обрабатывать десятки тысяч конкурентных соединений без создания отдельных системных потоков. |
| Единый стек (Fullstack JS) | Использование одного языка (JavaScript/TypeScript) как на фронтенде, так и на бэкенде упрощает повторное использование логики, валидаций и DTO. |
| Богатая экосистема | Крупнейший реестр пакетов NPM предоставляет готовые библиотеки для решения любых задач. |
| Высокая производительность движка V8 | Компиляция JavaScript напрямую в машинный код обеспечивает быстродействие CPU-легких операций. |

### 2. Как создать простой HTTP-сервер в Node.js?
Создание сервера осуществляется с помощью встроенного модуля `http` методом `createServer()`:

```javascript
const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify({ message: 'Сервер работает' }));
});

const PORT = 3000;
server.listen(PORT, () => {
  console.log(`Сервер запущен на http://localhost:${PORT}`);
});
```

### 3. В чем разница между методами GET, POST, PUT и DELETE?

| HTTP-метод | Назначение | Идемпотентность | Безопасность | Наличие тела (Body) |
| :--- | :--- | :--- | :--- | :--- |
| `GET` | Получение ресурса или коллекции | Да | Да | Нет (параметры в URL) |
| `POST` | Создание нового ресурса или выполнение действия | Нет | Нет | Да (JSON, формы и т.д.) |
| `PUT` | Полная замена существующего ресурса | Да | Нет | Да (новая версия объекта) |
| `DELETE` | Удаление указанного ресурса | Да | Нет | Обычно нет |

### 4. Что такое middleware и для чего оно используется?
**Middleware** (промежуточный обработчик) — это функция, выполняемая в цепочке обработки входящего HTTP-запроса между моментом его поступления на сервер и отправкой окончательного HTTP-ответа клиенту.

Функции middleware принимают аргументы `(req, res, next)` и решают задачи:
1. Логирование запросов (время, метод, IP, URL).
2. Аутентификация и проверка прав доступа (JWT, сессии).
3. Парсинг и валидация тела запроса (`JSON`, `urlencoded`).
4. Управление заголовками безопасности и CORS.
5. Раздача статических файлов.
6. Вызов `next()` для передачи управления следующему обработчику в цепочке.

### 5. Как обрабатывать различные HTTP-методы для одного URL?
В нативном Node.js свойство `req.method` содержит имя HTTP-глагола в верхнем регистре (`GET`, `POST`, `PUT`, `DELETE`). Обработка строится с помощью ветвления:

```javascript
const { pathname } = url.parse(req.url, true);

if (pathname === '/api/users') {
  switch (req.method) {
    case 'GET':
      return handleGetUsers(req, res);
    case 'POST':
      return handleCreateUser(req, res);
    default:
      res.writeHead(405, { 'Content-Type': 'application/json' });
      return res.end(JSON.stringify({ error: 'Method Not Allowed' }));
  }
}
```

### 6. Что такое CORS и зачем нужны соответствующие заголовки?
**CORS (Cross-Origin Resource Sharing)** — механизм безопасности браузеров, блокирующий сетевые AJAX/Fetch запросы к домену, протоколу или порту, отличным от источника загрузки страницы (Same-Origin Policy).

Чтобы разрешить кросс-доменные запросы, сервер обязан вернуть специальные HTTP-заголовки:
- `Access-Control-Allow-Origin: *` — указывает разрешенные источники (или конкретный origin);
- `Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS` — разрешенные HTTP-методы;
- `Access-Control-Allow-Headers: Content-Type, Authorization` — разрешенные пользовательские заголовки;
- Браузер перед сложными запросами отправляет предварительный preflight-запрос с методом `OPTIONS`, на который сервер должен ответить статусом `200 OK`.

### 7. Как организовать чтение тела POST-запроса в Node.js?
Объект `req` в Node.js является входящим потоком для чтения (`ReadableStream`). Данные передаются фрагментами (чанками):

```javascript
function readRequestBody(req) {
  return new Promise((resolve, reject) => {
    let body = '';
    req.on('data', chunk => {
      body += chunk.toString();
    });
    req.on('end', () => {
      try {
        const parsed = body ? JSON.parse(body) : {};
        resolve(parsed);
      } catch (err) {
        reject(new Error('Невалидный JSON'));
      }
    });
    req.on('error', err => reject(err));
  });
}
```
