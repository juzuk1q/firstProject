# Ответы на вопросы для самоконтроля: Практическая работа №17 («React: работа с формами»)

---

### 1. В чем разница между управляемыми и неуправляемыми компонентами в формах React?

| Критерий | Управляемые компоненты (Controlled) | Неуправляемые компоненты (Uncontrolled) |
| :--- | :--- | :--- |
| **Источник истины (Source of Truth)** | Состояние React (`useState` / `useReducer`). | Сам DOM-узел браузера. |
| **Получение данных** | Значение элемента всегда синхронизировано со свойством `value` из стейта. | Значение извлекается по запросу из DOM через хук `useRef` (`ref.current.value`). |
| **Отслеживание изменений** | Требуется обязательный обработчик `onChange`, обновляющий состояние на каждый ввод символа. | Обработчик `onChange` не обязателен; данные читаются однократно в момент отправки формы (`onSubmit`). |
| **Рендеринг** | Компонент перерендеривается при каждом изменении значения поля. | Ввод символов пользователем не вызывает повторных рендеров компонента. |
| **Начальное значение** | Задается через пропс `value`. | Задается через пропс `defaultValue` или `defaultChecked`. |

### 2. Когда следует использовать управляемые компоненты, а когда — неуправляемые?

**Управляемые компоненты следует использовать:**
1. **Мгновенная валидация «на лету»**: проверка формата email или надежности пароля прямо в процессе ввода.
2. **Динамическая блокировка элементов**: отключение кнопки отправки (disabled), пока все обязательные поля не заполнены корректно.
3. **Условное отображение полей**: показ дополнительных секций формы в зависимости от выбора пользователя (например, показ поля «Номер компании» только если выбран тип аккаунта «Юридическое лицо»).
4. **Маски и форматирование ввода**: автоформатирование номера телефона (`+7 (999) 000-00-00`) или номера банковской карты с пробелами.
5. **Связанные поля**: автоматический пересчет значений (например, конвертер валют).

**Неуправляемые компоненты следует использовать:**
1. **Простые статичные формы**: формы обратной связи, опросы, где данные нужны только в момент отправки и не требуют сложной динамики интерфейса.
2. **Работа с полями типа `file` (`<input type="file" />`)**: в HTML5 значение файлового инпута является доступным только для чтения из соображений безопасности браузера, поэтому в React файловые поля всегда реализуются как неуправляемые через `ref`.
3. **Интеграция со сторонними библиотеками**: интеграция с UI-плагинами jQuery, d3, текстовыми редакторами (TinyMCE, CKEditor) или сложными графическими канвасами.
4. **Оптимизация производительности**: гигантские формы на сотни динамических полей (data-grid, электронные таблицы), где ререндер всей формы на каждое нажатие клавиши может вызывать задержки.

### 3. Какие методы и события используются для обработки событий в формах React?

В формах React используются синтетические события (**SyntheticEvent**), которые унифицируют поведение браузеров:

1. **`onChange`**:
   - В отличие от нативного JS, в React событие `onChange` срабатывает при каждом нажатии клавиши / изменении значения в `<input>`, `<textarea>`, `<select>` (аналогично нативному событию `input`).
2. **`onSubmit`**:
   - Вешается на тег `<form>`. Срабатывает при клике на кнопку с `type="submit"` или при нажатии клавиши Enter в поле ввода.
3. **`onBlur`**:
   - Срабатывает, когда элемент теряет фокус. Идеально подходит для валидации поля после того, как пользователь закончил его заполнение и перешел к следующему.
4. **`onFocus`**:
   - Срабатывает при установке фокуса на элемент. Используется для очистки ошибок, показа всплывающих подсказок или подсветки активной строки.
5. **`onReset`**:
   - Срабатывает при нажатии кнопки с `type="reset"` или вызове метода очистки формы.
6. **`onKeyDown` / `onKeyUp`**:
   - Отслеживание нажатия конкретных клавиш (например, отправка сообщения по `Ctrl + Enter` или отмена по `Escape`).

### 4. Как обрабатывать несколько полей ввода с одним обработчиком?

Чтобы не создавать отдельную функцию-обработчик для каждого поля, используется универсальный обработчик на основе атрибута `name` и вычисляемых имен свойств объекта в ES6 (`[e.target.name]: value`).

**Пример реализации:**
```javascript
const [formData, setFormData] = useState({
  username: '',
  email: '',
  age: '',
  newsletter: false
});

const handleChange = (e) => {
  const { name, value, type, checked } = e.target;
  
  setFormData(prev => ({
    ...prev,
    // Для checkbox берем св-во checked, для остальных — value
    [name]: type === 'checkbox' ? checked : value
  }));
};

// В JSX:
// <input name="username" value={formData.username} onChange={handleChange} />
// <input name="email" value={formData.email} onChange={handleChange} />
// <input type="checkbox" name="newsletter" checked={formData.newsletter} onChange={handleChange} />
```
Этот подход масштабируется на любое количество полей без дублирования кода.

### 5. Какие подходы к валидации форм в React вы знаете?

1. **Встроенная HTML5-валидация**:
   - Использование стандартных HTML-атрибутов: `required`, `pattern`, `type="email"`, `minLength`, `max`.
   - *Плюсы*: работает «из коробки» без JS-кода.
   - *Минусы*: дизайн всплывающих окон привязан к браузеру и операционной системе, трудно стилизовать и локализовать.
2. **Кастомная валидация через State (ручной подход, реализованный в практической работе)**:
   - Создаются состояния `errors` (объект с текстами ошибок) и `touched` (отслеживание взаимодействий).
   - Валидация выполняется функциями на `onChange`, `onBlur` или `onSubmit`.
   - *Плюсы*: полный контроль над внешним видом, логикой и UX без сторонних зависимостей.
3. **Библиотеки управления формами с хуками (React Hook Form, Formik)**:
   - **React Hook Form**: использует неуправляемый подход с подписками на основе `ref`, что обеспечивает максимальную производительность без лишних ререндеров.
   - **Formik**: классический инструмент для декларативной работы с формами в React.
4. **Валидация по схеме (Schema-based validation: Zod, Yup, Joi)**:
   - Описание правил в виде декларативной схемы:
     ```javascript
     const schema = z.object({
       email: z.string().email('Некорректный email'),
       password: z.string().min(8, 'Минимум 8 символов')
     });
     ```
   - Легко интегрируется с React Hook Form через резолверы (`@hookform/resolvers/zod`).

### 6. Как предотвратить стандартное поведение формы (перезагрузку страницы)?

По умолчанию при отправке HTML-формы (`<form>`) браузер генерирует POST/GET-запрос и **перезагружает страницу**, сбрасывая все состояние JavaScript-приложения.

Чтобы отменить это поведение в React (для работы в режиме Single Page Application), необходимо вызвать метод **`e.preventDefault()`** у объекта события внутри обработчика `onSubmit`:

```javascript
const handleSubmit = (event) => {
  event.preventDefault(); // Предотвращает перезагрузку страницы и переход по URL
  
  // Дальнейшая обработка данных в SPA (валидация, отправка через fetch/axios):
  console.log('Отправка данных без перезагрузки страницы');
};
```

### 7. Что такое "поднятие состояния" (lifting state up) в контексте форм?

**Поднятие состояния (Lifting State Up)** — это архитектурный паттерн в React, при котором состояние перемещается из дочернего компонента вверх к их ближайшему общему предку.

**Применение в контексте форм:**
1. **Связанные шаги формы (Multi-step Form / Wizard)**:
   - Если форма разделена на шаги (`Step1Personal`, `Step2Address`, `Step3Payment`), хранить данные внутри каждого шага неудобно, так как при переходе на следующий шаг предыдущий компонент размонтируется и теряет стейт.
   - Общее состояние всей анкеты `formData` и функция его обновления хранятся в родительском компоненте `CheckoutForm`, который передает нужные поля и колбэки каждому дочернему шагу через `props`.
2. **Форма и независимый блок предварительного просмотра (Preview)**:
   - Поля ввода находятся в компоненте `<FormEditor />`, а отображение готовой карточки — в `<LivePreview />`.
   - Состояние формы поднимается в общего родителя `<App />`, который передает данные формы в `<FormEditor />` для редактирования и в `<LivePreview />` для мгновенного отображения.
