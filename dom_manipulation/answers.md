## 1. В чем разница между `innerHTML` и `textContent` и когда следует использовать каждый метод?
`textContent`:
  * Получает или задает текстовое содержимое узла и всех его потомков в виде обычного текста без парсинга HTML.
  * Все передаваемые теги экранируются и выводятся буквально как текст (`<b>текст</b>` отобразится именно как текст с тегами, а не жирным шрифтом).
  * Безопасность: полностью защищает от уязвимостей межсайтового скриптинга (XSS — Cross-Site Scripting), так как код браузера не парсит вставку как HTML/JS.
  * Производительность: работает быстрее `innerHTML`, поскольку браузер не задействует HTML-парсер.
  * Когда использовать: для вывода пользовательского ввода, динамических текстовых значений, счетчиков, заголовков и любого неразмеченного контента.

`innerHTML`:
  * Возвращает или заменяет всю внутреннюю HTML-разметку элемента.
  * Строка передается встроенному HTML-парсеру, который перестраивает поддерево DOM.
  * Риски: небезопасен при вставке непроверенных данных пользователя (риск XSS при вставке `<img src=x onerror=...>` или инъекции разметки). Кроме того, полная перезапись через `element.innerHTML += ...` приводит к уничтожению и пересозданию всех вложенных узлов, сбрасывая привязанные слушатели событий и состояние полей ввода.
  * Когда использовать: когда необходимо вставить или полностью заменить сложный HTML-шаблон с доверенным содержимым.

## 2. Как работает делегирование событий (event delegation) и какие преимущества оно дает при работе с динамическими элементами?
Механизм работы:
  Делегирование событий базируется на механизме всплытия (event bubbling): большинство событий (например, `click`, `change`, `keydown`) после срабатывания на целевом элементе поднимаются вверх по цепочке предков вплоть до `document` и `window`.
  Вместо назначения обработчика на каждый отдельный элемент мы вешаем один общий обработчик на их общего родителя (контейнер). Внутри обработчика проверяется источник события через `event.target` (или метод `event.target.closest(selector)`):
  ```javascript
  const list = document.getElementById('dynamic-list');
  list.addEventListener('click', function(event) {
      const deleteBtn = event.target.closest('.delete-btn');
      if (deleteBtn) {
          const item = deleteBtn.closest('.list-item');
          if (item) item.remove();
      }
  });
  ```
Преимущества:
- Поддержка динамических элементов:** элементы, добавляемые в список позже (через `append`, AJAX или ввод пользователя), сразу обрабатываются без необходимости вручную навешивать на них слушатели.
- Экономия памяти: один обработчик на контейнере вместо сотен или тысяч функций-обработчиков на каждом отдельном элементе.
- Упрощение кода: меньше логики при создании и удалении элементов (не нужно отписываться от событий для предотвращения утечек памяти при удалении узлов).

## 3. Какие методы используются для поиска элементов в DOM и в чем разница между `getElementById`, `querySelector` и `querySelectorAll`?

| Метод | Что ищет | Возвращаемое значение | Особенности |
| :--- | :--- | :--- | :--- |
| `getElementById(id)` | Один элемент по точному совпадению ID. | `HTMLElement` или `null`. | Самый быстрый метод поиска в DOM (использует внутренний хэш-индекс браузера). Принимает только строку идентификатора без символа `#`. |
| `querySelector(selector)` | Первый элемент, соответствующий любому CSS-селектору. | Первый найденный `Element` или `null`. | Универсальный метод, поддерживает сложные селекторы (классы `.item`, атрибуты `[type="text"]`, псевдоклассы `:first-child`, вложенность `#parent > .child`). |
| `querySelectorAll(selector)` | Все элементы, подходящие под CSS-селектор. | Статическая коллекция `NodeList`. | Коллекция статична (не "живая"): добавление новых элементов в DOM не меняет уже полученный `NodeList`. Поддерживает метод `.forEach()`. Для использования методов массивов легко конвертируется через `Array.from()`. |

Устаревшие методы: `getElementsByClassName` и `getElementsByTagName` возвращают «живые» коллекции `HTMLCollection`, которые автоматически обновляются при изменении DOM, что часто приводит к неочевидным багам при итерациях. Современным стандартом является использование пары `querySelector` / `querySelectorAll`.

## 4. Как предотвратить стандартное поведение элемента при обработке событий и когда это необходимо?
Метод:** `event.preventDefault()` — отменяет стандартное действие браузера, ассоциированное с данным событием.
Когда это необходимо:
  1. Отправка форм (`submit`): предотвращение стандартной перезагрузки страницы или отправки HTTP-запроса браузером для выполнения валидации на клиенте и отправки через AJAX/Fetch (`handleFormSubmit(e) { e.preventDefault(); ... }`).
  2. Переход по ссылкам (`click` на `<a>`): когда ссылка используется как триггер интерфейса (модальное окно, таб, вкладка), а не для перехода на новый URL.
  3. Контекстное меню (`contextmenu`): для переопределения стандартного меню браузера на собственное кастомное контекстное меню.
  4. Ограничение ввода текста (`keydown`, `keypress`): запрет ввода недопустимых символов в текстовое поле (например, блокировка ввода букв в числовое поле).
  5. Drag-and-Drop (`dragover`, `drop`): для разрешения сброса файлов в браузерную область вместо их открытия браузером.

## 5. В чем разница между `classList.add()` и `className` для работы с CSS классами?
`element.className`:
  * Представляет собой просто строку, содержащую весь атрибут `class`.
  * Присваивание (`element.className = "active-style"`) полностью перезаписывает все существующие классы элемента. Чтобы добавить класс, приходится вручную конкатенировать строки (`element.className += " active-style"`), что чревато дублированием классов и ошибками с пробелами.
`element.classList` (интерфейс `DOMTokenList`):
  * Современный специализированный API для точечной работы с классами.
  * Предоставляет удобные методы:
    * `classList.add('cls1', 'cls2')` — добавляет классы (дубликаты автоматически игнорируются).
    * `classList.remove('cls')` — удаляет указанный класс, не затрагивая остальные.
    * `classList.toggle('cls')` — переключает наличие класса (добавляет, если нет; удаляет, если есть).
    * `classList.contains('cls')` — проверяет наличие класса (возвращает `true`/`false`).
    * `classList.replace('old', 'new')` — заменяет один класс на другой.
Вывод:** во всех современных проектах рекомендуется использовать `classList`, так как он защищает от случайного затирания других служебных классов элемента.

## 6. Как создать новый элемент и добавить его в DOM несколькими способами? Какой способ наиболее эффективен?
Основные способы:
  1. `document.createElement(tagName)` + методы вставки (`append`, `appendChild`):**
     ```javascript
     const div = document.createElement('div');
     div.className = 'card';
     div.textContent = 'Контент';
     target.append(div);
     ```
     Плюсы: полный контроль над узлом, безопасность (нет XSS), возможность сразу повесить обработчики событий.
  2. `element.insertAdjacentHTML(position, htmlString)`:
     ```javascript
     target.insertAdjacentHTML('beforeend', '<div class="card"><p>Контент</p></div>');
     ```
     Плюсы: парсит HTML-строку и вставляет узлы в точную позицию (`beforebegin`, `afterbegin`, `beforeend`, `afterend`) без перезаписи существующих узлов родителя.
  3. Использование `DocumentFragment`:
     Легковесный виртуальный контейнер, не являющийся частью основного дерева документа:
     ```javascript
     const fragment = document.createDocumentFragment();
     items.forEach(text => {
         const li = document.createElement('li');
         li.textContent = text;
         fragment.appendChild(li);
     });
     target.appendChild(fragment); // Однократная вставка в DOM!
     ```
Какой способ наиболее эффективен:
  * При пакетном добавлении множества элементов `DocumentFragment` наиболее эффективен, так как он вызывает ровно один перерасчет макета (Reflow) и одну перерисовку (Repaint).
  * Для одиночных элементов или динамических списков отлично подходит комбинация `document.createElement()` + `append()`, либо `insertAdjacentHTML()`.

## 7. Что такое всплытие событий (event bubbling) и как работает метод `stopPropagation()`?
Фазы обработки событий:
  Когда происходит событие (например, клик по кнопке внутри вложенных `div`), оно проходит три фазы:
  1. *Фаза погружения (Capturing phase)* — событие идет от `window` вниз через всех предков к целевому элементу.
  2. *Фаза цели (Target phase)* — событие достигает элемента `event.target`.
  3. *Фаза всплытия (Bubbling phase)* — событие поднимается обратно вверх от `event.target` к родителям: `parent` $\to$ `section` $\to$ `body` $\to$ `html` $\to$ `document` $\to$ `window`.

Метод `event.stopPropagation()`:
  * Немедленно останавливает дальнейшее движение события вверх по цепочке предков на текущей или последующих фазах.
  * Обработчики на родительских элементах больше не узнают об этом событии.
Разница со `stopImmediatePropagation()`:
  * `stopPropagation()` прекращает всплытие к предкам, но другие обработчики на *этом же самом элементе* выполнятся.
  * `stopImmediatePropagation()` останавливает и всплытие, и выполнение всех остальных обработчиков данного события на текущем элементе.
**Важно:** злоупотреблять `stopPropagation()` не следует без явной необходимости (например, в модальных окнах для предотвращения закрытия при клике на само окно), так как это может сломать работу глобальных систем аналитики и механизмы делегирования событий.

## 8. Как получить данные из формы и в чем разница между методами сбора form data?
Метод 1: Прямое обращение к элементам формы (по ID или имени):
  ```javascript
  const name = document.getElementById('user-name').value;
  const email = form.elements['user-email'].value;
  ```
  Применение: отлично подходит для небольших форм с несколькими конкретными полями.
Метод 2: Использование конструктора `new FormData(form)`:
  ```javascript
  const formData = new FormData(userForm);
  const data = Object.fromEntries(formData.entries());
  // { name: "...", email: "...", age: "..." }
  ```
  Преимущества:
  * Автоматически собирает все поля формы, у которых задан атрибут `name`.
  * Корректно обрабатывает чекбоксы, радиокнопки, мультиселекты и файловые инпуты (`<input type="file">`).
  * Готов к непосредственной отправке через `fetch(url, { method: 'POST', body: formData })`.
Метод 3: Сериализация через `URLSearchParams`:
  ```javascript
  const params = new URLSearchParams(new FormData(form)).toString();
  ```
  Применение: удобно для формирования GET-запросов со строкой параметров запроса.

## 9. Какие события используются для обработки ввода данных и в чем разница между `input`, `change` и `keyup`?

| Событие | Момент срабатывания | Особенности и применение |
| :--- | :--- | :--- |
| **`input`** | **Немедленно** при каждом фактическом изменении значения поля. | Срабатывает при печати с клавиатуры, вставке текста мышью (через контекстное меню «Вставить»), удалении, распознавании речи, автозаполнении браузером. Идеально для живого поиска, фильтрации на лету и синхронизации (`setupInputDisplay`). |
| **`change`** | **После завершения редактирования** и потери фокуса элементом (событие `blur`). | Для `<input type="text">` не срабатывает при каждом нажатии клавиши, а ждет расфокусировки. Для `<input type="checkbox">`, `<input type="radio">` и `<select>` срабатывает сразу при выборе значения. Идеально для финальной валидации поля. |
| **`keyup`** | В момент **отпускания физической клавиши** на клавиатуре. | Реагирует на клавиатурные события, включая служебные клавиши (Shift, ArrowLeft, Esc), которые не меняют значение текста. **Не срабатывает**, если текст был вставлен или изменен с помощью мыши. Используется для горячих клавиш (например, отправка по Enter). |

## 10. Как оптимизировать производительность при частых манипуляциях с DOM?
Прямое обращение к DOM является ресурсоемкой операцией («дорогой»), так как изменение структуры дерева или геометрических стилей заставляет браузер выполнять Reflow (перерасчет геометрии/макета) и Repaint (перерисовку пикселей)
Ключевые техники оптимизации:
1. **Батчинг (пакетная вставка) через `DocumentFragment`:**
   Вместо добавления элементов в цикле по одному (`target.appendChild(el)` $\times 1000$), добавлять их во фрагмент памяти и затем вставить в DOM один раз.
2. **Использование `requestAnimationFrame`:**
   Синхронизация визуальных изменений DOM и анимаций с частотой обновления экрана монитора (обычно 60 Гц / 144 Гц), предотвращая пропуск кадров.
3. **Кэширование селекторов DOM:**
   Не вызывать `document.getElementById` или `document.querySelector` на каждой итерации цикла; сохранить ссылку на элемент в переменную и переиспользовать.
4. **Техники Debounce и Throttle:**
   Ограничение частоты срабатывания обработчиков ресурсоемких событий (`scroll`, `resize`, `mousemove`, ввод текста в поиске) для предотвращения спама перерасчетов макета.
5. **Делегирование событий:**
   Назначение одного слушателя на родительский узел вместо сотен обработчиков на дочерних элементах сокращает расход оперативной памяти.
6. **Изменение классов вместо инлайн-стилей:**
   Вместо последовательного изменения множества свойств `element.style.width`, `element.style.height`, `element.style.color` выгоднее переключить один CSS-класс (`classList.add('active-style')`), объединяя все изменения стилей в один цикл перерисовки.
7. **Скрытие элемента перед массовой модификацией (`display: none`):**
   Элемент с `display: none` удаляется из дерева рендеринга. Массовые изменения внутри него не вызывают Reflow на странице; после завершения манипуляций элемент снова отображается.
